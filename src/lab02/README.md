# Лабораторная работа №2 - Коллекция объектов

## Класс ServerCollection

### Реализованные методы

| Метод | Описание |
|-------|----------|
| `add(server)` | Добавить сервер |
| `remove(server)` | Удалить сервер |
| `get_all()` | Получить все серверы |
| `find_by_name(hostname)` | Поиск по имени |
| `find_by_ip(ip)` | Поиск по IP |
| `find_by_status(status)` | Поиск по статусу |
| `remove_at(index)` | Удаление по индексу |
| `sort_by_hostname()` | Сортировка по имени |
| `get_active_servers()` | Получить активные серверы |

### Магические методы

- `__len__()` — длина коллекции
- `__iter__()` — итерация в цикле for
- `__getitem__()` — доступ по индексу

## Сценарии использования

### Сценарий 1: Базовые операции с коллекцией

**Что демонстрирует:** инициализацию коллекции, добавление и удаление узлов, использование магических методов `__len__` и `__iter__`.

**Как работает:** Инициализируется коллекция с названием "Production". В неё помещаются три сервера: `web-01`, `db-01` и `cache-01`. Функция `len()` показывает общее число элементов. Цикл `for` через `__iter__` обходит все записи и печатает их имена. После этого `cache-01` исключается через `remove()`, и список выводится заново — в нём остаётся два сервера.

### Сценарий 2: Поиск и ограничения коллекции

**Что демонстрирует:** методы поиска (`find_by_name`, `find_by_ip`, `find_by_status`) и механизмы защиты от дублей и некорректных типов.

**Как работает:** Формируется коллекция из четырёх серверов с различными статусами (`active`, `inactive`, `maintenance`). Выполняется поиск по имени `db-master` и адресу `10.0.0.2`. `find_by_status` отбирает все активные серверы и выводит их количество. Затем проверяется защита: попытка добавить сервер с занятым IP бросает `ValueError`, передача строки вместо объекта Server — `TypeError`.

### Сценарий 3: Индексация, сортировка и фильтрация

**Что демонстрирует:** обращение к элементам по индексу через `__getitem__`, удаление по позиции методом `remove_at`, упорядочивание коллекции и выборку активных узлов в отдельный список.

**Как работает:** Собирается коллекция из пяти серверов с именами в произвольном порядке (`zebra`, `alpha`, `main`, `beta`, `gamma`). Показывается доступ по индексам `[0]`, `[2]` и `[-1]`. Вызов `remove_at(1)` исключает второй элемент. Далее `sort_by_hostname()` выстраивает серверы в алфавитном порядке. `get_active_servers()` возвращает новую коллекцию только с активными серверами, демонстрируя гибкую фильтрацию данных.
