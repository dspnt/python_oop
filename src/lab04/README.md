# Лабораторная работа №4 - Интерфейсы и абстрактные классы (ABC)

## 1. Цель работы
Освоение абстрактных базовых классов (ABC) в Python, понимание интерфейса как контракта поведения, закрепление полиморфизма через единый интерфейс.

## 2. Описание интерфейсов
Определено 4 абстрактных класса (интерфейса) в файле `interfaces.py`:

| Интерфейс | Методы | Назначение |
|-----------|--------|------------|
| **IManageable** | `activate()`, `deactivate()`, `get_status()` | Управление состоянием объекта |
| **IMonitorable** | `calculate_load()`, `get_info()` | Мониторинг и сбор метрик |
| **IComparable** | `compare_to(other)` | Сопоставление объектов друг с другом |
| **IPrintable** | `to_string()` | Представление объекта в виде строки |

## 3. Реализация в классах

### Базовый класс `Server` (из ЛР-3)
Реализует интерфейсы `IManageable` и `IMonitorable`.

### Класс `WebServer`
- Реализует `IManageable` (наследует), `IMonitorable` (переопределяет), `IComparable`, `IPrintable`
- **Сравнение:** по имени хоста (алфавитный порядок)
- **Нагрузка:** базовая + 0.5% за каждый обработанный запрос

### Класс `DatabaseServer`
- Реализует `IManageable` (наследует), `IMonitorable` (переопределяет), `IComparable`, `IPrintable`
- **Сравнение:** по текущей нагрузке
- **Нагрузка:** базовая + 0.3% за каждый выполненный запрос

### Класс `FileServer`
- Реализует `IManageable` (наследует), `IMonitorable` (переопределяет), `IPrintable`
- **Не реализует** `IComparable`
- **Нагрузка:** базовая + 2% за каждый загруженный файл

## 4. Демонстрация

### Сценарий 1: Базовые интерфейсы

**Что демонстрирует:** проверку реализации интерфейсов через `isinstance()`, вызов методов с различным поведением для разных классов.

**Как работает:** Инициализируются объекты `WebServer`, `DatabaseServer`, `FileServer`. Для каждого проверяется набор реализуемых интерфейсов. Вызываются `get_info()` и `calculate_load()`, демонстрирующие собственную логику каждого типа сервера.

### Сценарий 2: Универсальные функции через интерфейсы

**Что демонстрирует:** построение функций, работающих с любыми объектами через интерфейс, без привязки к конкретным классам.

**Как работает:**
- `print_all_printable()` принимает произвольные объекты с интерфейсом `IPrintable` и выводит их через `to_string()`
- `compare_by_interface()` выполняет сравнение объектов через `IComparable`
- `get_all_loads()` собирает показатели нагрузки через `IMonitorable`

### Сценарий 3: Фильтрация коллекции по интерфейсам

**Что демонстрирует:** отбор объектов из коллекции по реализуемым интерфейсам, полиморфизм без ветвлений.

**Как работает:** Формируется коллекция из 7 серверов разных типов. Выполняется выборка объектов, реализующих `IPrintable` и `IComparable`. Сравниваются анти-паттерн (явная проверка типа через `isinstance`) и Good-паттерн (вызов метода через интерфейс).

## 5. Вывод

В ходе лабораторной работы были изучены следующие концепции:

- **Абстрактные базовые классы (ABC)** — определение интерфейсов через наследование от `ABC` и декоратор `@abstractmethod`
- **Интерфейс как контракт** — обязательная реализация заданных методов в классах-наследниках
- **Множественная реализация интерфейсов** — один класс может одновременно реализовывать несколько интерфейсов
- **Полиморфизм через интерфейс** — единообразный вызов методов для объектов разных классов
- **Фильтрация по интерфейсу** — выборка объектов по реализуемым интерфейсам с помощью `isinstance()`
