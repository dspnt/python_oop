# Лабораторная работа 1: Класс и инкапсуляция

## Вопрос 1. Что является сущностью?

**Ответ: Сервер (Server)**

В данной предметной области реально существует объект **сервер** — физический или виртуальный компьютер в IT-инфраструктуре, который:

- Имеет сетевое имя (hostname)
- Имеет IP-адрес
- Находится в одном из возможных состояний (активен, неактивен, обслуживание)
- Принимает подключения от пользователей
- Поддерживает ограничение на количество одновременных соединений

Это конкретный объект реальной IT-инфраструктуры, а не абстрактная концепция.

---

## Вопрос 2. Какие у него атрибуты?

### Атрибуты-характеристики (данные):

| Атрибут | Тип | Описание |
|---------|-----|----------|
| `hostname` | строка | Имя сервера (например, "web-01") |
| `ip_address` | строка | IP-адрес в формате IPv4 |
| `status` | строка | Текущее состояние: "active", "inactive", "maintenance" |
| `max_connections` | число | Максимальное количество одновременных подключений |
| `current_connections` | число | Актуальное количество активных подключений |
| `created_at` | дата/время | Момент создания сервера |
| `users` | список | Список подключённых в данный момент пользователей |

### Атрибуты-действия (методы):

| Метод | Описание |
|-------|----------|
| `connect_user(username)` | Подключить пользователя к серверу |
| `disconnect_user(username)` | Отключить пользователя от сервера |
| `activate()` | Активировать сервер |
| `deactivate()` | Деактивировать сервер |
| `maintenance_mode()` | Перевести сервер в режим технического обслуживания |

## Вопрос 3. Какие инварианты?

**Инварианты класса Server** — правила, которые должны соблюдаться в любой момент времени:

### Инварианты для hostname:

- `hostname` не может быть пустой строкой
- `hostname` допускает только буквы, цифры и дефис
- Длина `hostname` не превышает 63 символов

### Инварианты для ip_address:

- IP-адрес должен соответствовать формату IPv4 (4 октета, разделённых точками)
- Каждый октет находится в диапазоне 0–255

### Инварианты для status:

- `status` принимает только одно из значений: `"active"`, `"inactive"`, `"maintenance"`

### Инварианты для подключений:

- `current_connections` всегда ≥ 0
- `current_connections` всегда ≤ `max_connections`

### Инварианты для max_connections:

- `max_connections` всегда > 0
- `max_connections` ≤ 1000 (разумное техническое ограничение)

### Бизнес-инварианты (логические правила):

- При статусе `"maintenance"` значение `current_connections` равно 0
- При статусе `"inactive"` значение `current_connections` равно 0

## Вопрос 4. Что значит "равенство"?

**Два сервера считаются равными, если у них совпадает IP-адрес.**

---

## Вопрос 5. Есть ли состояние?

**Да, сервер может находиться в одном из трёх состояний:**

1. **`"active"` (активен)** — сервер работает в штатном режиме, подключения разрешены
2. **`"inactive"` (неактивен)** — сервер выключен или недоступен, подключения невозможны
3. **`"maintenance"` (обслуживание)** — сервер проходит техническое обслуживание, подключения невозможны

## Описание класса Server

### Атрибут класса

Класс содержит один **атрибут класса** — `os_type` (тип операционной системы). Он является общим для всех экземпляров и наглядно демонстрирует разницу между атрибутами класса и экземпляра. Значение по умолчанию — `"Linux"`, что соответствует типичному серверному окружению.

### Конструктор

Конструктор `__init__` принимает следующие параметры:

- `hostname` *(обязательный)* — имя сервера
- `ip_address` *(обязательный)* — IP-адрес сервера
- `max_connections` *(необязательный, по умолчанию 100)* — лимит подключений
- `status` *(необязательный, по умолчанию `"inactive"`)* — начальный статус

При создании объекта выполняются следующие шаги:

1. Все переданные параметры проходят валидацию через функции модуля `validate.py`
2. Инициализируются закрытые атрибуты
3. Устанавливаются значения по умолчанию: `current_connections = 0`, `created_at = текущее время`
4. Создаётся пустой список для хранения подключённых пользователей

Если хотя бы один параметр не проходит валидацию, конструктор выбрасывает исключение — объект не создаётся.

### Свойства (`@property`)

Для контролируемого доступа к закрытым атрибутам используются свойства, позволяющие выполнять дополнительную логику при чтении и записи значений.

#### Только для чтения (геттеры)

| Свойство | Описание |
|----------|----------|
| `hostname` | Возвращает имя сервера |
| `ip_address` | Возвращает IP-адрес сервера |
| `current_connections` | Возвращает текущее число подключений |
| `created_at` | Возвращает дату и время создания сервера |

#### С возможностью изменения (геттер + сеттер)

**`status`:**
- геттер возвращает текущий статус
- сеттер проверяет допустимость нового значения
- запрещает переход из `"active"` в `"maintenance"` при наличии активных подключений
- выводит сообщение об изменении статуса

**`max_connections`:**
- геттер возвращает текущий лимит подключений
- сеттер проверяет, что новое значение — положительное целое число, не превышающее 1000
- запрещает уменьшение лимита ниже текущего числа подключений
- выводит сообщение об изменении лимита

## Демонстрация работы (`demo.py`)

### Сценарий 1: Базовый

**Что демонстрирует:** создание объекта, работу магических методов `__str__`, `__repr__` и `__eq__`.

**Как работает:** создаётся сервер с именем `"web-01"`, IP `"192.168.1.100"`, лимитом 5 и статусом `"inactive"`. Выводится его представление через `print` (вызывается `__str__`) и через `repr`. Затем создаются ещё два сервера: один с тем же IP, другой — с отличающимся. Сравнение подтверждает, что серверы с одинаковым IP считаются равными вне зависимости от имени, а с разными IP — различными.
