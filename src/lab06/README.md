# Лабораторная работа №6 - Generics и typing

## 1. Цель работы
Освоить систему аннотаций типов в Python (typing), научиться создавать обобщённые (generic) классы с помощью `TypeVar` и `Generic`, разобраться с концепцией структурной типизации через `typing.Protocol`.

## 2. Описание реализованных типов и контейнеров

### Generic-коллекция `TypedCollection[T]`
Обобщённая версия коллекции из ЛР-2. Хранит элементы строго одного типа T.

**Методы:**

- **`add(item: T) -> None`** — Поместить элемент в коллекцию.
- **`remove(item: T) -> None`** — Исключить элемент из коллекции.
- **`get_all() -> list[T]`** — Вернуть список всех элементов.
- **`__len__() -> int`** — Возвращает количество элементов, позволяет использовать `len()`.
- **`__iter__()`** — Возвращает итератор для использования в цикле `for`.
- **`__getitem__(index: int) -> T`** — Доступ к элементу по индексу: `collection[0]`.
- **`find(predicate: Callable[[T], bool]) -> Optional[T]`** — Находит первый подходящий элемент или возвращает `None`.
- **`filter(predicate: Callable[[T], bool]) -> list[T]`** — Возвращает все элементы, удовлетворяющие условию.
- **`map(transform: Callable[[T], R]) -> list[R]`** — Применяет функцию к каждому элементу и возвращает список результатов, тип которых может отличаться от исходного (например, `TypedCollection[Server]` → `list[str]`).

### TypeVar

- **`T`** — Тип элементов коллекции. Используется для построения Generic-класса.
- **`R`** — Тип результата после `map()`. Может отличаться от `T`.
- **`D`** — Тип с ограничением `bound=Displayable`. Для коллекций объектов с методом `display()`.
- **`S`** — Тип с ограничением `bound=Scorable`. Для коллекций объектов с методом `score()`.

### Protocol (структурная типизация)

**`Displayable`** — протокол, требующий наличия метода `display() -> str`. Любой класс с таким методом автоматически ему соответствует — без явного наследования.

**`Scorable`** — протокол, требующий наличия метода `score() -> float`.

Классы из ЛР-3 (`Server`, `WebServer`, `DatabaseServer`, `FileServer`) не наследуют эти протоколы напрямую, но имеют нужные методы (добавлены через `add_protocol_methods()`), поэтому подходят под них. В этом и заключается структурная типизация — объект принимается, если он делает то, что требуется, а не потому что является наследником.

### Сценарий 2: find, filter, map

**Что демонстрирует:** работу методов `find()`, `filter()`, `map()` с различными функциями.

**Как работает:**
- `find()` — поиск существующего и отсутствующего элемента
- `filter()` — выборка активных серверов и веб-серверов
- `map()` — преобразование в список строк (имена) и список чисел (нагрузка)

Показывается изменение типа результата `map`: `list[str]` и `list[float]`.

### Сценарий 3: Protocol и bound

**Что демонстрирует:** применение `TypedCollection` с ограничением по протоколам `Displayable` и `Scorable`.

**Как работает:**
- Создаётся `TypedCollection[D]` с ограничением `Displayable`
- Добавляются объекты разных типов (`WebServer`, `DatabaseServer`, `FileServer`)
- Объекты не наследуют протокол явно, но имеют метод `display()` — и этого достаточно
- Для каждого объекта безопасно вызывается `display()`, так как протокол гарантирует наличие метода

Аналогично для `TypedCollection[S]` с протоколом `Scorable`.

## 4. Вывод

В ходе лабораторной работы были изучены следующие концепции:

- **Аннотации типов** — параметры, возвращаемые значения, атрибуты классов
- **Generic** — `TypeVar` и `Generic` для построения обобщённых классов
- **TypedCollection** — контейнер, обеспечивающий хранение элементов одного типа
- **find, filter, map** — методы с корректными аннотациями типов
- **Protocol** — структурная типизация (объект подходит, если имеет нужные методы, без явного наследования)
- **Bound** — ограничение `TypeVar` через протокол
